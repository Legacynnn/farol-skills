# Brand

Identity beyond the interface. `DESIGN.md` holds the system the UI is built from; this holds who the product is when it speaks, is named, or is seen from a distance.

## Name

- Product name, capitalisation, pronunciation, what it means and why.
- Names of the parts (plans, features, roles) and the rule for naming new ones.

## Story

Three sentences: where it came from, what it stands against, where it is going.

## Voice

How it sounds in marketing, onboarding, support and errors. Three adjectives and the anti-adjectives, with one example line each.

| Context | Sounds like | Never like |
| --- | --- | --- |
| Marketing | | |
| Product UI | see `DESIGN.md` Copy | |
| Support | | |

## Marks

- Logo files and the rule for each variant (colour, mono, mark-only), clear space, minimum size, backgrounds.
- Where the marks live in the repo.

## Imagery

Photography, illustration and iconography direction: subjects, treatment, what is never shown.

## Feel

The one sentence a user should be able to say after a week with the product.
